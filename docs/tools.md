## `capi_drain_node`

```text
Drain a management cluster node, by name or CAPI Machine: cordon it and evict its pods, respecting PodDisruptionBudgets.

Reaches only the management cluster's API: a workload cluster Machine's node is looked up there by name, so it fails, or drains a management cluster node of the same name (giantswarm/mcp-capi#302). Cordons first, then refuses, evicting nothing, when a DaemonSet pod, an unmanaged pod or emptyDir data would need ignore_daemonsets, force or delete_local_data. Waits until evicted pods are gone; the node stays cordoned either way. Cordon alone: capi_cordon_node.
```

```json
{
  "properties": {
    "delete_local_data": {
      "description": "Evict pods with emptyDir volumes, losing that data",
      "type": "boolean"
    },
    "force": {
      "description": "Evict pods no controller manages; they are not recreated",
      "type": "boolean"
    },
    "grace_period_seconds": {
      "description": "Termination grace period of the evicted pods (default: each pod's own)",
      "type": "number"
    },
    "ignore_daemonsets": {
      "description": "Leave DaemonSet pods on the node instead of refusing the drain",
      "type": "boolean"
    },
    "machine_name": {
      "description": "Name of a Machine; a workload cluster Machine's node name is looked up on the management cluster",
      "type": "string"
    },
    "namespace": {
      "description": "Namespace of the machine",
      "type": "string"
    },
    "node_name": {
      "description": "Name of the node (alternative to machine)",
      "type": "string"
    },
    "timeout_seconds": {
      "description": "Give up after this many seconds, waiting for PodDisruptionBudgets and terminating pods (default: 120)",
      "type": "number"
    }
  },
  "required": [],
  "type": "object"
}
```
